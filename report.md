# Отчёт по практической работе CI/CD

## 1. Что сделал

Создал workflow GitHub Actions для автоматической проверки сайта. Перенёс файлы сайта, тесты и скрипт сборки в корень репозитория.

Workflow находится в `.github/workflows/ci.yml`. При отправке коммита в ветку `main` автоматически запускаются тесты, затем сборка сайта и сохранение артефакта.

## 2. Первый запуск

Первый запуск прошёл успешно, все 4 теста завершились без ошибок.

Коммит: `109b793` — `added CI`.

После тестов выполнилась сборка сайта. В GitHub Actions появился артефакт `lesson-site`, который содержит собранные файлы сайта.

Скачал артефакт и проверил `release.json`. В нём указан коммит:

`109b793fadf6aa9494396d883ed3d1977c383aee`

Артефакт можно скачать из GitHub Actions, но это не означает, что сайт опубликован в интернете.

## 3. Проверка ошибки

Перед изменением файла `site/index.html` предположил, что при замене `style.css` на `missing.css` упадёт тест `test_stylesheet_exists`, потому что такого CSS-файла нет.

Также ожидал, что после ошибки шаги `Build site` и `Save site artifact` не выполнятся.

Изменил ссылку и отправил отдельный коммит.

Коммит с ошибкой: `d9f2594`.

[Красный запуск GitHub Actions](https://github.com/ipsergei/ci-cd-practice-for-3-course/actions/runs/44523358185)

В результате 3 теста прошли, а `test_stylesheet_exists` завершился с ошибкой.

Причина из журнала:

```text
AssertionError: False is not true : Missing stylesheet: missing.css
```

Шаги `Build site` и `Save site artifact` были пропущены, потому что тестирование завершилось с ошибкой. Новый артефакт для этого запуска не создавался.

Таким образом, прогноз подтвердился.

## 4. Исправление ошибки

Вернул правильную ссылку `href="style.css"`.

Коммит с исправлением: `7780c75`.

[Зелёный запуск после исправления](https://github.com/ipsergei/ci-cd-practice-for-3-course/actions/runs/44523874269)

После исправления все 4 теста прошли успешно. Шаги `Build site` и `Save site artifact` тоже выполнились, артефакт `lesson-site` был создан.

Предыдущий красный запуск остался в истории GitHub Actions, так как он проверял другую версию проекта.

## 5. Изменение аудитории

В отдельном коммите изменил `Аудитория: 301` на `Аудитория: 302`.

Коммит: `fd43b0b`.

[Запуск после изменения аудитории](https://github.com/ipsergei/ci-cd-practice-for-3-course/actions/runs/44524216340)

Предполагал, что тесты пройдут успешно, поскольку они не проверяют правильность номера аудитории.

Так и получилось: все 4 теста прошли, сайт собрался и артефакт сохранился.

Это показывает, что зелёные тесты не гарантируют отсутствие всех ошибок. Они проверяют только то, что предусмотрено самими тестами.

## 6. Где выполнялись тесты

Тесты выполнялись не на моём компьютере, а на GitHub Actions runner с Ubuntu (`ubuntu-latest`).

Runner получает файлы репозитория, подготавливает Python 3.12 и запускает тесты.

Результаты сохраняются на GitHub, потому что workflow выполняется на инфраструктуре GitHub Actions. Там остаются журналы проверок, статусы запусков и артефакты успешных сборок.

## 7. Вывод

В ходе практической работы разобрался, как работает автоматическая проверка после коммита.

Убедился, что GitHub Actions обнаруживает ошибки, останавливает последующие шаги при неуспешных тестах и сохраняет результаты проверок.

Также понял, что успешные тесты не означают, что в проекте вообще нет ошибок. Они подтверждают только выполнение проверяемых условий.
